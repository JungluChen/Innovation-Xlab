01 · Workflow

Fibula turns reconciliation intent into stateful workflows.

Operators describe matching requirements in plain language, then watch Fibula turn that intent into reviewable workflow structure.

Stage 1 Natural Language Prompting

Operators explain reconciliation intent in plain language, including matching requirements, variance thresholds, escalation rules, and exception handling expectations.

  • Describe matching rules in natural language without complex configuration forms
  • Set variance thresholds and tolerance ranges for each document type
  • Define escalation paths for exceptions that exceed acceptable variance

Stage 2 Agentic Workflow Synthesis

Fibula synthesizes node-based workflow structures that connect source documents, logic branches, and exception states into a coherent process representation.

  • Intent-to-node translation preserves the operator's original logic in every step
  • Automatic dependency mapping connects document sources to matching rules
  • Multi-document state tracking handles PO, INV, GRN, BOM, and WO simultaneously

Stage 3 Human-in-the-Loop Validation

Generated workflows remain reviewable so teams can inspect nodes, verify assumptions, and adjust the synthesis before live execution.

  • Interactive node inspection lets operators verify every step before deployment
  • Pre-deployment simulation validates workflow behavior against sample data
  • Approval chain configuration routes validation to the right stakeholders

Stage 4 Stateful Live Deployment

Deployed workflows keep state across matching decisions, output handling, retries, and exception resolution instead of resetting to stateless extraction outputs.

  • Cross-session state persistence preserves context across interruptions and restarts
  • Real-time exception handling surfaces variance flags without halting the workflow
  • Audit-ready decision log records every match, override, and approval with full metadata

02 · Method

Research evidence moves through the same product workflow.

Document logic, think-aloud behavior, and repeated friction were treated as evidence files before interface changes were made.

Evidence 1 Workflow Mapping

Map document logic before interface fixes.

Document types, matching keys, variance decisions, and exception paths were mapped before visual fixes were proposed.

  • Map document types across AP and BOM reconciliation flows
  • Identify matching keys and trace variance decisions
  • Translate workflow ambiguity into product requirements

Evidence 2 Task-based Testing

Observe users without steering their choices.

More than 15 unguided think-aloud sessions captured hesitation, misclicks, confusion, and abandonment across participant cohorts.

  • Run more than 15 unguided think-aloud sessions
  • Record hesitation, misclicks, confusion, and abandonment
  • Compare behavior across 11 participant cohorts

Evidence 3 Success Framework

Evidence-based coding prioritized repeated friction.

The 90 percent No-Help Rule kept testing consistent and translated repeated friction logs into concrete product fixes.

  • Apply the 90 percent No-Help Rule
  • Use evidence-based coding rather than subjective preference
  • Keep core evidence visible without hover-only disclosure

04 · Fixes

Findings archive into concrete product corrections.

The redesign is shown as a sequence of files moving from observed friction to specific workflow fixes.

Fix 1 Spatial Desynchronization

Users needed visible workflow construction.

Silent processing made the workflow feel disconnected from the user's mental model.

Problem
Users could not connect intent to system output
Fix
Draw workflow nodes as synthesis happens
Impact
Users can see progress and system activity

Fix 2 Convenience Bias

Choice overload pushed users toward the quickest path.

Verbose option lists caused users to select convenient paths rather than correct reconciliation flows.

Problem
Too many visible choices
Fix
Predictive chips and progressive disclosure
Impact
Faster choices with less cognitive burden

Fix 3 Operational Opacity

Failure states needed visible recovery paths.

Silent errors and dead-end modals left users without a clear way to recover inside the workflow.

Problem
Unclear error recovery
Fix
Advice cards, rerun shortcuts, next-step guidance
Impact
Users recover without leaving the workflow

Pipeline restored — every junction visible.

05 · Impact

The workflow ends as visible, auditable reconciliation confidence.

Fibula reduces hidden automation risk by keeping intent, exception handling, and human validation visible from start to deployment.

Impact 1 Mental Model Gap

Users needed visible system guidance, not silent synthesis.

The redesign makes natural-language intent visible as executable structure and reduces uncertainty during automation.

  • Immediate guidance from the first action
  • Live feedback while workflows are synthesized
  • Visible bridge from intent to structure

Impact 2 Reconciliation Risk Mitigation

Clear exception visibility protects industrial decisions.

Fibula turns outputs into clearer decision surfaces where variance, exception states, and human validation remain visible.

  • Expose missed variance and unclear output risk
  • Make exception states visible and recoverable
  • Keep human validation in the automation loop
